# API Contract

The frontend expects the backend to follow this contract **exactly**.
All request and response bodies are JSON. Base path: `/api`.

---

## Data shape: Certificate

```json
{
  "cert_id": "CERT-9F3A21BC",
  "recipient_name": "Priya Nair",
  "recipient_email": "priya.nair@example.com",
  "course_name": "Flask Web Development",
  "issue_date": "2026-03-25",
  "status": "active",
  "revoked_at": null,
  "created_at": "2026-03-25T10:15:00+00:00"
}
```

| Field | Notes |
|---|---|
| `cert_id` | Public ID. Format `CERT-` + 8 uppercase hex characters. Generated by the server. Unique. |
| `recipient_email` | Stored in lowercase. |
| `issue_date` | `YYYY-MM-DD`. |
| `status` | `"active"` or `"revoked"`. |
| `revoked_at` | ISO 8601 UTC timestamp, or `null` if not revoked. |
| `created_at` | ISO 8601 UTC timestamp. Set by the server. |

## Error format (every error response)

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Invalid input",
    "details": { "recipient_email": "Must be a valid email address" }
  }
}
```

`details` is only included for validation errors on specific fields (keyed by field name).

| HTTP status | `code` | When |
|---|---|---|
| 400 | `BAD_REQUEST` | Body is missing or is not a JSON object |
| 400 | `VALIDATION_ERROR` | Body or query parameters fail validation |
| 401 | `UNAUTHORIZED` | Not logged in, or wrong email / password |
| 404 | `NOT_FOUND` | Certificate does not exist |
| 409 | `CONFLICT` | Business rule conflict (see below) |
| 502 | `SMTP_ERROR` | The email server could not be reached, or sending failed (see "Email setup") |

## Authentication

Users sign up and log in with an email and password. After a successful sign-up or login,
the server sets a **session cookie**. The browser sends it with every request, so the
frontend doesn't need to handle tokens.

| Endpoint | Login needed? |
|---|---|
| `POST /api/auth/signup`, `POST /api/auth/login`, `GET /api/health` | No |
| `GET /api/verify/<cert_id>` | No, verification is public |
| Every other `/api/certificates...` endpoint | **Yes.** Without a valid session → `401 UNAUTHORIZED` |

### Data shape: User

```json
{
  "id": 1,
  "name": "Priya Nair",
  "email": "priya.nair@example.com",
  "created_at": "2026-03-25T10:15:00+00:00"
}
```

A user response **never** includes the password or its hash.

### A1. Sign up

`POST /api/auth/signup`

```json
{ "name": "Priya Nair", "email": "priya.nair@example.com", "password": "at-least-8-chars" }
```

| Field | Rule |
|---|---|
| `name` | Required. String. 2–100 characters after trimming spaces. |
| `email` | Required. Valid email format. Stored in lowercase. Must be unique. |
| `password` | Required. String. 8–128 characters. Not trimmed. |

- `201 Created` → `{ "data": <User> }`, and the user is now logged in
- `400` → `BAD_REQUEST` or `VALIDATION_ERROR` (all failing fields in `details`)
- `409` → `CONFLICT` if an account with that email already exists

### A2. Log in

`POST /api/auth/login`

```json
{ "email": "priya.nair@example.com", "password": "at-least-8-chars" }
```

The email is case-insensitive.

- `200` → `{ "data": <User> }`, and the user is now logged in
- `400` → `VALIDATION_ERROR` if `email` or `password` is missing
- `401` → `UNAUTHORIZED` with the message `"Invalid email or password"` (same message whether the email or the password is wrong)

### A3. Log out

`POST /api/auth/logout` → `204 No Content`. The session ends.

### A4. Current user

`GET /api/auth/me`

- `200` → `{ "data": <User> }`
- `401` → `UNAUTHORIZED` if not logged in

## 1. Create a certificate

`POST /api/certificates`

**Login required.**

**Request body**

```json
{
  "recipient_name": "Priya Nair",
  "recipient_email": "priya.nair@example.com",
  "course_name": "Flask Web Development",
  "issue_date": "2026-03-25"
}
```

**Validation rules**

| Field | Rule |
|---|---|
| `recipient_name` | Required. String. 2–100 characters after trimming spaces. |
| `recipient_email` | Required. Valid email format. |
| `course_name` | Required. String. 2–150 characters after trimming spaces. |
| `issue_date` | Required. Format `YYYY-MM-DD`. Must not be in the future. |

Report **all** failing fields at once in `details`, not just the first one.

**Business rule:** a recipient (by email) cannot have two **active** certificates for the same course (case-insensitive). If they already do, return **409 CONFLICT**. A new certificate is allowed if the old one was revoked.

**Responses**

- `201 Created` → `{ "data": <Certificate> }`
- `400` → `BAD_REQUEST` or `VALIDATION_ERROR`
- `409` → `CONFLICT`

---

## 2. List certificates

`GET /api/certificates`

**Login required.**

**Query parameters (all optional)**

| Param | Default | Rule |
|---|---|---|
| `page` | `1` | Whole number ≥ 1 |
| `limit` | `10` | Whole number, 1–50 |
| `search` | – | Case-insensitive partial match on `recipient_name` |
| `status` | – | `active` or `revoked` |

Invalid values → `400 VALIDATION_ERROR`.
Results are ordered **newest first**.

**Response `200`**

```json
{
  "data": [ <Certificate>, ... ],
  "pagination": { "page": 1, "limit": 10, "total": 23, "pages": 3 }
}
```

When there are no results: `data` is `[]`, `total` is `0`, `pages` is `0`.

---

## 3. Get one certificate

`GET /api/certificates/<cert_id>`

**Login required.**

- `200` → `{ "data": <Certificate> }`
- `404` → `NOT_FOUND`

---

## 4. Verify a certificate (public)

`GET /api/verify/<cert_id>`

**No login needed.**

**Response `200`** (note: no `data` wrapper, and the email is **not** included, because this endpoint is public)

```json
{
  "cert_id": "CERT-9F3A21BC",
  "valid": true,
  "status": "active",
  "recipient_name": "Priya Nair",
  "course_name": "Flask Web Development",
  "issue_date": "2026-03-25",
  "revoked_at": null
}
```

`valid` is `true` only when `status` is `active`.

- `404` → `NOT_FOUND`

---

## 5. Revoke a certificate

`PATCH /api/certificates/<cert_id>/revoke`

**Login required.**

No request body needed.

- `200` → `{ "data": <Certificate> }` with `status: "revoked"` and `revoked_at` set
- `404` → `NOT_FOUND`
- `409` → `CONFLICT` if it is already revoked

## Email setup (Gmail / SMTP)

Each user can connect **one** email account. CertDesk uses it to email certificates to
recipients. It works with Gmail through a Google **App Password** (Gmail rejects normal
passwords for SMTP), or with any other SMTP server.

The frontend for this is already built: the *Email setup* tab, and the email option on the
*Issue* form. **Login required** for every endpoint in this section.

### Data shape: EmailSettings

```json
{
  "email": "academy@gmail.com",
  "from_name": "CertDesk Academy",
  "smtp_host": "smtp.gmail.com",
  "smtp_port": 587,
  "verified_at": "2026-03-25T10:15:00+00:00"
}
```

The app password is **never** returned by any endpoint.

### E1. Get my email settings

`GET /api/email-settings`

- `200` → `{ "data": <EmailSettings> }`, or `{ "data": null }` if email isn't set up yet

### E2. Save (and check) my email settings

`PUT /api/email-settings`

```json
{
  "from_name": "CertDesk Academy",
  "email": "academy@gmail.com",
  "app_password": "abcd efgh ijkl mnop",
  "smtp_host": "smtp.gmail.com",
  "smtp_port": 587
}
```

| Field | Rule |
|---|---|
| `from_name` | Optional. String, up to 100 characters after trimming. Empty or missing → the user's name. |
| `email` | Required. Valid email format. Stored in lowercase. This is the address emails are sent **from**. |
| `app_password` | Required. String. Spaces are removed first (Google shows it as 4 groups of 4). 1–128 characters after that. |
| `smtp_host` | Required. A host name, for example `smtp.gmail.com`. |
| `smtp_port` | Required. Whole number, 1–65535. Port `465` uses SSL; any other port uses STARTTLS. |

**Before saving, the server must log in to the SMTP server with these details**, then log
out. Save only if the login works. A successful save replaces any earlier settings.

- `200` → `{ "data": <EmailSettings> }` with `verified_at` set to now
- `400` → `VALIDATION_ERROR` for the field rules above, **or** when the SMTP server rejects the
  login. In that case: `"details": { "app_password": "Gmail did not accept this email and app password" }`
- `502` → `SMTP_ERROR` if the server can't connect to `smtp_host:smtp_port` (wrong host or port, timeout)

### E3. Send a test email

`POST /api/email-settings/test`

Sends a short test email from the saved account to the **logged-in user's** email address.

- `200` → `{ "data": { "sent_to": "you@example.com" } }`
- `409` → `CONFLICT` if email isn't set up
- `502` → `SMTP_ERROR` if sending failed

### E4. Disconnect

`DELETE /api/email-settings` → `204 No Content`. Deletes the saved settings, including the
app password. Also `204` if nothing was saved.

### E5. Email a certificate to its recipient

`POST /api/certificates/<cert_id>/send-email`

Sends the certificate to its `recipient_email`, from the logged-in user's saved account
(`From: "<from_name>" <email>`). The frontend calls this right after issuing a certificate,
when email is set up and the "Email the certificate" box is ticked.

You choose the subject and body, but the email must include the recipient's name, the course,
the issue date, the certificate ID, and how to verify it.

- `200` → `{ "data": { "cert_id": "CERT-9F3A21BC", "sent_to": "priya.nair@example.com", "sent_from": "CertDesk Academy <academy@gmail.com>" } }`
- `404` → `NOT_FOUND`
- `409` → `CONFLICT` if email isn't set up, or the certificate is revoked
- `502` → `SMTP_ERROR` if sending failed

## Bulk issue

Bulk issue lets a logged-in user upload a CSV file, review each row before it is issued, and then
approve the upload to issue the ready rows in the background while the user keeps working.

### B1. Upload a CSV and preview the rows

`POST /api/bulk-issues`

**Login required.**

**Request**: multipart form-data with a single file field named `file`.

- `file` must be a UTF-8 CSV file.
- `1 MB` max size, `500` rows max.
- The file must include the header row and at least these columns: `recipient_name`,
  `recipient_email`, `course_name`, `issue_date`.
- Extra columns are ignored; empty lines are skipped.

**Response `200`**

```json
{
  "job_id": "BULK-9BEA4FA12C3D",
  "status": "pending",
  "summary": { "total": 3, "ready": 2, "errors": 1, "issued": 0, "failed": 0 },
  "rows": [
    { "row_number": 1, "recipient_name": "Priya Nair", "recipient_email": "priya.nair@example.com", "course_name": "Flask Web Development", "issue_date": "2026-03-25", "status": "ready", "error": null },
    { "row_number": 2, "recipient_name": "Rohan Mehta", "recipient_email": "rohan.mehta@example.com", "course_name": "Flask Web Development", "issue_date": "2026-03-25", "status": "ready", "error": null },
    { "row_number": 3, "recipient_name": "Bad Row", "recipient_email": "bad-email", "course_name": "Flask Web Development", "issue_date": "2026-03-25", "status": "error", "error": "Must be a valid email address" }
  ]
}
```

- `400` → `VALIDATION_ERROR` if the CSV is missing, empty, too large, invalid UTF-8, missing required columns, or has no data rows.

The preview must validate every row using the same rules as the single-certificate API; rows with
problems are marked as `status: "error"` instead of being issued. Nothing is issued yet.

### B2. Approve and start issuing

`POST /api/bulk-issues/<job_id>/approve`

**Login required.**

Returns immediately once the server has accepted the job. The actual certificate creation then happens
in the background.

- `202 Accepted` → `{ "job_id": "BULK-9BEA4FA12C3D", "status": "processing" }`
- `404` → `NOT_FOUND` if the job does not belong to the logged-in user
- `409` → `CONFLICT` if the job was already approved, started, or has no rows ready to issue

### B3. Get job status and results

`GET /api/bulk-issues/<job_id>`

**Login required.**

Returns the current state of the job and the per-row result list.

**Response `200`**

```json
{
  "job": {
    "job_id": "BULK-9BEA4FA12C3D",
    "filename": "students.csv",
    "status": "completed",
    "summary": { "total": 3, "ready": 2, "errors": 1, "issued": 2, "failed": 0 },
    "created_at": "2026-03-25T10:15:00+00:00",
    "started_at": "2026-03-25T10:16:00+00:00",
    "completed_at": "2026-03-25T10:16:02+00:00",
    "rows": [
      { "row_number": 1, "recipient_name": "Priya Nair", "recipient_email": "priya.nair@example.com", "course_name": "Flask Web Development", "issue_date": "2026-03-25", "status": "issued", "error": null, "cert_id": "CERT-A1B2C3D4" },
      { "row_number": 2, "recipient_name": "Rohan Mehta", "recipient_email": "rohan.mehta@example.com", "course_name": "Flask Web Development", "issue_date": "2026-03-25", "status": "issued", "error": null, "cert_id": "CERT-E5F6G7H8" },
      { "row_number": 3, "recipient_name": "Bad Row", "recipient_email": "bad-email", "course_name": "Flask Web Development", "issue_date": "2026-03-25", "status": "error", "error": "Must be a valid email address", "cert_id": null }
    ]
  }
}
```

- `404` → `NOT_FOUND` if the job isn't yours

### B4. Download the results as CSV

`GET /api/bulk-issues/<job_id>/results.csv`

**Login required.**

Returns a CSV file with one row per upload row and its final status.

- `200` → CSV attachment
- `404` → `NOT_FOUND`

The CSV columns are: `row_number`, `recipient_name`, `recipient_email`, `course_name`, `issue_date`,
`status`, `cert_id`, `error`.
